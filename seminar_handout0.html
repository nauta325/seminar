PART 1
기본 노션 강의 — 손으로 익히는 기초
01
STEP 1
페이지와 블록 — 노션의 최소 단위
1
노션은 "페이지"와 "블록"으로 되어 있어요

노션의 모든 화면은 페이지예요. 그리고 페이지 안에 들어가는 글자 한 줄, 제목 하나, 표 하나가 모두 블록이에요.

워크스페이스
→
페이지
→
블록

즉, 페이지 = 종이, 블록 = 그 위에 얹는 조각이라고 생각하면 쉬워요. 텍스트, 제목, 체크박스, 이미지, 표 전부 블록이에요.

2
새 페이지 만들기 — 이렇게 하세요
  • 왼쪽 사이드바에서 + 새 페이지 (또는 사이드바 상단 검색 아래 +)를 눌러요.
  • 맨 위 큰 칸에 페이지 제목을 적어요. 예: 우리 학원
  • 제목 아래 본문 칸을 클릭하면 커서가 깜빡여요. 여기가 첫 번째 블록이에요.
  • 왼쪽에 마우스를 올리면 나오는 ⋮⋮ (점 6개)를 드래그하면 블록 순서를 바꿀 수 있어요.
💡 핵심 단축키 "/" (슬래시)
본문에서 /를 입력하면 넣을 수 있는 블록 메뉴가 쫙 떠요. 여기서 원하는 블록을 고르면 돼요. 오늘 제일 많이 쓰는 키예요.
3
기본 블록 넣어보기 — 직접 따라해요
  • /제목1 (또는 /h1) → 큰 제목 블록. /제목2, /제목3은 조금씩 작은 제목이에요.
  • 그냥 글자를 치면 텍스트(본문) 블록이에요. 가장 기본이에요.
  • /구분선 → 가로줄이 생겨 내용을 시각적으로 나눠줘요.
  • /글머리 기호 → 점(•) 목록, /번호 목록 → 1. 2. 3. 목록.
  • /할 일 목록 → 체크박스가 생겨요. 클릭하면 체크돼요.
✅ 알아두면 편한 것
이미 쓴 블록도 왼쪽 ⋮⋮ → 전환으로 종류를 바꿀 수 있어요. (예: 텍스트 → 제목1) 처음부터 완벽하게 안 골라도 괜찮아요.
☑ 실습 체크 — 아래를 직접 만들어보세요
"우리 학원"이라는 이름의 새 페이지를 만들었다
/제목1로 큰 제목을 하나 넣었다
/구분선과 /할 일 목록을 넣어봤다

STEP 2
학생 명단 · 강사 데이터베이스 만들기
1
데이터베이스(표)가 뭐예요?

데이터베이스는 엑셀 표처럼 생긴, 똑똑한 표예요. 한 줄(행)이 학생 한 명이고, 각 칸(열)이 그 학생의 정보예요. 노션에서는 이 열 하나하나를 속성(Property)이라고 불러요.

행 = 학생 1명
×
열 = 속성(정보)
2
학생 명단 DB 만들기 — 이렇게 하세요
  • 새 페이지에서 /데이터베이스를 입력해요. 데이터베이스 - 전체 페이지를 고르면 표가 페이지 하나를 꽉 채워요. (페이지 안에 작게 넣으려면 인라인을 선택)
  • DB 제목을 학생 명단으로 정해요.
  • 맨 왼쪽 이름 열은 기본으로 있는 제목 속성이에요. 여기에 학생 이름을 적어요.
  • 오른쪽 끝 + (열 추가)를 눌러 속성을 하나씩 더해요.
  • 속성 이름과 유형을 정해요. 유형을 잘 고르는 게 중요해요 (아래 표 참고).
속성(열) 추천 유형
이름제목 (기본)
연락처전화번호
학년선택 (초1, 초2 …)
과목다중 선택 (영어, 수학 …)
재원 상태선택 (재원 / 휴원)
⚠️ "선택" vs "텍스트"
학년·과목처럼 정해진 값이 반복되면 선택 유형을 쓰세요. 나중에 필터·색상·그룹화가 훨씬 편해요. 자유롭게 적는 메모만 텍스트로 하세요.
3
강사 DB도 같은 방식으로

강사 명단도 똑같은 방법으로 하나 더 만들어요. 나중에 학생과 연결할 거라 따로 만드는 것이 핵심이에요.

  • 새 페이지 → /데이터베이스 → 제목 강사 명단
  • 속성: 이름(제목), 연락처(전화번호), 담당 과목(다중 선택), 근무 요일(다중 선택)
  • 강사 한 명씩 행을 추가해 채워요.
✅ 왜 학생·강사를 나눠서 만들까요?
다음 단계에서 두 표를 관계형으로 연결하면, "이 강사가 맡은 학생"이 저절로 모여요. 그래서 지금은 각각 깔끔하게 만들어 두는 게 중요해요.
☑ 실습 체크
"학생 명단" DB를 만들고 속성 5개를 넣었다
학생 2~3명을 실제로 입력해봤다
"강사 명단" DB도 만들었다

STEP 3
관계형(Relation)과 롤업(Rollup)
1
관계형 — 두 표를 서로 연결하기

관계형은 학생 명단과 강사 명단을 서로 이어주는 기능이에요. "이 학생의 담당 강사는 누구"라고 연결해두면, 반대로 강사 쪽에서 "내가 맡은 학생들"이 자동으로 모여요.

학생 명단
↔
강사 명단
2
관계형 연결하기 — 이렇게 하세요
  • 학생 명단 DB에서 + (열 추가) → 유형에서 관계형(Relation)을 골라요.
  • 연결할 데이터베이스로 강사 명단을 선택해요.
  • 속성 이름을 담당 강사로 정해요.
  • 양방향 표시(강사 명단에도 표시)를 켜요. 그러면 강사 쪽에도 자동으로 담당 학생 열이 생겨요.
  • 이제 학생마다 담당 강사 칸을 클릭해 강사를 지정하면, 강사 쪽에 학생이 저절로 쌓여요.
💡 여기서 감탄 포인트
강사 쪽에 학생을 따로 안 적었는데도, 학생 쪽에서 강사를 지정한 것만으로 강사의 "담당 학생" 목록이 저절로 채워져요. 한 번만 연결하면 양쪽이 동시에 관리돼요.
3
롤업 — 연결된 표에서 숫자·값 가져오기

관계형으로 이어놓으면, 롤업으로 연결된 쪽의 정보를 끌어와 계산할 수 있어요. 대표 예시가 담당 학생 수 세기예요.

  • 강사 명단 DB에서 + (열 추가) → 유형 롤업(Rollup) 선택.
  • 관계형: 담당 학생 (아까 자동 생성된 연결)을 골라요.
  • 속성: 이름을 골라요.
  • 계산: 개수(Count)를 선택해요. → 강사별 담당 학생 수가 숫자로 나와요.
✅ 다른 롤업 예시
계산을 원본 표시로 바꾸면 학생 이름 목록을 그대로 볼 수 있어요. 숫자 속성이라면 합계·평균도 가능해요.
💡
관계형 → 롤업, 순서가 중요해요
① 관계형으로 연결
학생 ↔ 강사
→
② 롤업으로 계산
담당 학생 수

롤업은 관계형이 먼저 있어야 작동해요. 연결이 없으면 가져올 게 없거든요. "연결 먼저, 계산 나중"만 기억하세요.

☑ 실습 체크
학생 명단에 "담당 강사" 관계형을 만들었다
강사 쪽에 "담당 학생"이 자동으로 생긴 걸 확인했다
롤업으로 강사별 "담당 학생 수"를 세어봤다

STEP 4
할 일 DB와 뷰(View)
1
할 일 데이터베이스 만들기
  • 새 페이지 → /데이터베이스 → 제목 할 일
  • 속성: 할 일(제목), 상태(선택: 예정 / 진행중 / 완료), 마감일(날짜), 담당(관계형 → 강사 명단)
  • 할 일 몇 개를 입력해요. 예: "9월 교재 주문", "레벨테스트 준비" 등
⚠️ "상태" 속성이 핵심
뒤에서 보드(칸반) 뷰로 바꿀 때 선택 속성이 있어야 칸이 나뉘어요. 그래서 상태를 선택 유형으로 꼭 만들어 두세요.
2
뷰(View) — 같은 데이터, 다른 화면

데이터는 하나인데, 보는 방법(뷰)은 여러 개예요. 표를 지웠다 다시 만드는 게 아니라, 같은 표를 다르게 펼쳐 보는 거예요.

📋 표(Table)
🗂 보드(Board·칸반)
📅 캘린더
  • DB 왼쪽 위 뷰 이름 옆 + (보기 추가)를 눌러요.
  • 보드를 고르고, 그룹화 기준을 상태로 정해요. → 예정 / 진행중 / 완료 칸이 생기고 카드를 끌어 옮길 수 있어요.
  • 다시 + 보기 추가 → 캘린더를 고르고 마감일 기준으로 표시해요. → 달력에 할 일이 뜹니다.
💡 데이터는 그대로, 창만 늘어나요
한 DB에 표 뷰 + 보드 뷰 + 캘린더 뷰를 동시에 둘 수 있어요. 보드에서 카드를 "완료"로 옮기면, 표 뷰에서도 상태가 완료로 바뀌어요. 같은 데이터니까요.
3
필터 · 정렬 · 그룹화 — 원하는 것만 꺼내기
  • 필터(Filter) — 조건에 맞는 것만 보기
    예: 상태 = 진행중
  • 정렬(Sort) — 순서대로 줄 세우기
    예: 마감일 빠른 순
  • 그룹화(Group) — 같은 값끼리 묶기
    예: 담당 강사별로 묶기
  • DB 오른쪽 위 ··· (점 세 개) 또는 필터 버튼에서 설정해요.
✅ 뷰별로 저장돼요
한 뷰에 필터를 걸어도 다른 뷰에는 영향이 없어요. 그래서 "내 할 일만 보는 뷰", "이번 주 마감 뷰"를 따로 만들어 둘 수 있어요.
☑ 실습 체크
"할 일" DB를 만들고 상태 속성을 넣었다
보드 뷰 · 캘린더 뷰를 추가했다
필터로 "진행중"만 보이게 해봤다

STEP 5
학원 홈 한 페이지로 조립
1
흩어진 DB를 한 페이지에 모으기

지금까지 학생 명단·강사 명단·할 일 DB를 각각 만들었어요. 이제 이걸 학원 관리 홈 한 페이지에 모아서, 여기만 열면 다 보이게 만들어요.

📗 학생 명단
👩‍🏫 강사 명단
✅ 할 일
→
🏫 학원 관리 홈
2
홈 페이지 조립하기 — 이렇게 하세요
  • 새 페이지를 만들고 제목을 학원 관리 홈으로 정해요.
  • 본문에서 /링크된 데이터베이스 보기를 입력해요. (원본을 옮기지 않고 "보여주기"만 하는 기능이에요)
  • 목록에서 학생 명단을 골라요. → 홈에 학생 명단이 그대로 떠요.
  • 같은 방법으로 강사 명단, 할 일도 링크로 불러와요.
  • 각 사이에 /제목2로 소제목을 넣거나 /구분선으로 나누면 보기 좋아요.
⚠️ "링크된 보기"와 "원본"의 차이
링크된 보기는 원본 DB를 창처럼 비추는 거예요. 홈에서 값을 고쳐도 원본이 같이 바뀌어요(같은 데이터니까요). 홈에서는 필터·정렬만 따로 걸어 "홈 전용 화면"을 만들 수 있어요.
3
강사에게 공유하기 (권한 설정)
  • 홈 페이지 오른쪽 위 공유 버튼을 눌러요.
  • 강사의 이메일을 입력해 초대해요.
  • 권한을 정해요: 전체 허용 / 편집 가능 / 댓글 가능 / 읽기 가능.
  • 강사에게는 보통 편집 가능 또는 읽기 가능이 적당해요. (설정 자체를 못 바꾸게 하려면 편집 가능까지)
✅ 하위 페이지도 함께 공유돼요
홈을 공유하면 그 안에 연결된 DB들도 접근 권한이 따라가요. 그래서 홈 한 번만 공유하면 강사가 필요한 걸 다 볼 수 있어요.
☑ 실습 체크
"학원 관리 홈" 페이지를 만들었다
링크된 보기로 DB 3개를 불러왔다
공유 버튼과 권한 옵션을 확인했다

STEP 6
학부모에게 공지를 공유할 때 주의점
1
두 가지 공유 방법을 구분하세요
👤 이메일 초대
특정 사람만 들어와요. 강사처럼 정해진 사람과 협업할 때 써요.
🌐 웹에 게시(링크 공유)
링크가 있으면 누구나 봐요. 학부모 공지처럼 여러 명에게 뿌릴 때 써요. 대신 주의가 필요해요.
2
학부모 공지 안전하게 공유하기 — 이렇게 하세요
  • 공지 전용 페이지를 따로 만들어요. (학생 명단·강사 DB가 들어있는 홈을 그대로 뿌리면 절대 안 돼요)
  • 페이지 오른쪽 위 공유 → 게시(웹에 게시) 탭을 열어요.
  • 링크 편집 허용은 끄기(읽기 전용)로 두세요. 학부모가 내용을 고치면 안 되니까요.
  • 필요하면 검색 엔진 색인 옵션을 꺼서 구글 검색에 안 뜨게 해요.
  • 생성된 링크만 복사해 단톡방·문자로 보내요.
⚠️
개인정보 — 꼭 지켜주세요
  • 학생 명단·연락처가 든 페이지를 통째로 링크 공유하지 마세요. 링크만 있으면 남의 정보까지 다 보여요.
  • 공지에는 전체 학생 이름·전화번호를 넣지 마세요. 개별 안내는 개별로 보내요.
  • 권한은 항상 읽기 전용으로. "편집 가능"으로 뿌리면 학부모가 내용을 바꿀 수 있어요.
  • 공유를 멈추고 싶으면 공유 → 게시 → 게시 취소로 링크를 즉시 닫을 수 있어요.
💡 한 줄 요약
"공지는 공지 전용 페이지만, 읽기 전용으로, 개인정보 빼고." 이 세 가지만 지켜도 사고가 안 나요.

이메일 초대와 웹 게시의 차이를 이해했다

개인정보 주의사항 3가지를 확인했다

Claude에 노션 연결하는 법
1
커넥터가 뭐예요?

커넥터(Connector)는 Claude와 내 노션을 이어주는 다리예요. 연결해두면 Claude에게 "노션에 학생 DB 만들어줘" 같은 말을 하면, Claude가 직접 내 노션을 읽고 만들어줄 수 있어요.

🤖 Claude
↔
📗 내 노션
2
연결하기 — 이렇게 하세요
  • Claude 화면에서 설정 → 커넥터(Connectors)로 들어가요.
  • 목록에서 Notion을 찾아 연결을 눌러요.
  • 노션 로그인 창이 뜨면 내 계정으로 로그인해요.
  • 액세스 허용(권한 승인) 화면에서, Claude가 접근할 페이지/워크스페이스 범위를 정해요.
  • 허용하면 연결 완료. 이제 대화 중에 노션을 읽고 쓸 수 있어요.
⚠️
권한 범위 — 딱 필요한 만큼만
  • 권한 화면에서 어디까지 접근을 허용하는지 꼭 확인하세요. "전체 워크스페이스" vs "특정 페이지만"은 큰 차이예요.
  • 가능하면 실습용 페이지 하나만 골라 접근을 허용하세요. 전체를 열면 학생 개인정보까지 AI가 볼 수 있어요.
  • 연결은 언제든 설정 → 커넥터에서 해제할 수 있어요. 세미나가 끝나면 필요 없을 때 꺼두세요.
💡 안전 원칙
"최소 권한" — 지금 필요한 페이지만 열어주고, 끝나면 닫는다. 개인정보가 든 실제 학생 DB는 되도록 연결 범위에서 빼두세요.
☑ 실습 체크
Claude 설정에서 Notion 커넥터를 찾았다
권한 범위 화면에서 "어디까지 허용"인지 확인했다
실습용 페이지만 골라 연결해봤다

1
이번엔 "구경하는" 시간이에요

1부에서 손으로 만든 걸, 이번엔 말로만 시켜서 AI가 만드는 걸 함께 봐요. 직접 안 만들어도 돼요. 어떻게 만들어지는지 흐름을 눈으로 익히는 게 목표예요.

🗣 말로 요청
→
🤖 Claude가 생성
→
📗 노션에 DB·뷰 완성
2
이렇게 말해보세요 — 요청 예시
"내 노션에 학원 관리용 데이터베이스를 만들어줘.
· 학생 명단 (이름, 연락처, 학년, 과목, 재원 상태)
· 강사 명단 (이름, 연락처, 담당 과목)
· 두 DB를 관계형으로 연결하고,
· 강사별 담당 학생 수를 롤업으로 세는 속성도 넣어줘.
· 할 일 DB는 보드 뷰랑 캘린더 뷰도 만들어줘."

이렇게 원하는 구조를 구체적으로 말할수록 결과가 정확해요. Claude가 위 요청대로 DB·관계형·롤업·뷰까지 순서대로 만들어주는 걸 함께 확인해요.

3
만들어진 뒤엔 꼭 확인!
  • AI가 만든 DB에 속성 유형이 내 의도와 맞는지 봐요. (예: 학년이 "선택"인지 "텍스트"인지)
  • 관계형이 제대로 연결됐는지, 롤업 숫자가 맞게 나오는지 확인해요.
  • 필요하면 손으로 조금 다듬어요. AI는 초안을 빠르게, 마무리는 사람이.
⚠️ AI도 가끔 틀려요
이름을 살짝 다르게 만들거나, 뷰를 빠뜨릴 수 있어요. 그래서 1부에서 배운 구조를 알고 있어야 "어디가 틀렸는지" 바로 잡을 수 있어요. (→ 다음 STEP 9)

STEP 9
왜 1부(기초)를 먼저 하는가
1
구조를 알아야 AI 결과도 쓸 수 있어요

AI가 DB를 대신 만들어주면 편하죠. 하지만 관계형·롤업·뷰가 뭔지 모르면, AI가 만든 것도 고치거나 활용하지 못해요. 결국 "만들어졌는데 어떻게 쓰는지 모르는" 상태가 돼요.

1부: 구조 이해
DB·관계형·롤업·뷰
→
2부: AI로 빠르게
말로 자동 생성
→
내 것으로 활용
수정·확장 자유
2
기초가 있으면 이런 게 가능해져요
  • AI 결과가 틀렸을 때 어디가 틀렸는지 바로 알아요.
  • 더 구체적으로 요청할 수 있어요. ("롤업 계산을 합계로 바꿔줘" 처럼)
  • AI가 만든 걸 내 학원 상황에 맞게 직접 수정·확장할 수 있어요.
  • AI 없이도 언제든 스스로 만들 수 있어요. 진짜 내 도구가 되는 거예요.
